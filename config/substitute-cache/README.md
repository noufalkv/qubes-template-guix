# Qubes channel substitute-cache signing key

`signing-key.pub` is the **public** Ed25519 signing key for the Qubes channel's
GitHub Pages substitute cache (built and published by
`.github/workflows/substitute-cache.yml`, generated by
`scripts/build-substitute-cache.sh`).

> **Security hold (July 22, 2026):** this cache is disabled in the template and
> its publication workflow is manual-and-fail-closed.  Earlier cache objects
> were built by a Guix 1.5.0 bootstrap daemon that predates the fixes in the
> [July 2 substitute/pull advisory][advisory].  Do not consume or republish
> those objects.  Re-enabling requires a clean builder running a verified fixed
> daemon, a newly generated signing key, and rebuilt templates that authorize
> only that new key.

[advisory]: https://guix.gnu.org/en/blog/2026/guix-substitute-pull-vulnerabilities/

It is stored as a **bare canonical s-expression with no comments** on purpose:
both `guix archive --authorize` and the template's `local-file` +
`authorized-keys` wiring read it directly, and `guix archive --authorize`
rejects a key file that contains comments ("Bad character in S-expression").

## Trust model

When enabled, trust is by **signature**, not by transport. The template would
authorize the active key and add the Pages cache URL to `guix-daemon` (see
`%qubes-substitute-cache-url`, `%qubes-substitute-cache-key-file`, and the
`%qubes-substitute-cache-enabled?` flag in `(qubes services)`). The daemon
accepts a cached nar only if it verifies against this key, so GitHub Pages (the
static host) does not need to be trusted.

The committed key is currently retired and the enable flag is `#f`; new
templates neither authorize it nor add this cache URL.

For substitutes to be useful the published outputs must be **reproducible**:
every custom Qubes derivation has been checked bit-for-bit with
`guix build --check --rounds=2`, so a user's locally computed store hash matches
the published nar and the substitute is actually used.

## Private key

The matching private key is **not committed**. It must live in the repository
Actions secret `GUIX_SIGNING_KEY_SEC` (Settings -> Secrets and variables ->
Actions) so the workflow can sign nars. This is a **dev** key; provision a
maintained key before any production use.

## Rotation (breaking change)

Rotating the key invalidates every already-published narinfo signature and every
template that authorized the old key. Rotation is mandatory before lifting the
current security hold: regenerate, update `GUIX_SIGNING_KEY_SEC` and
`signing-key.pub` together, rebuild the cache on a verified fixed daemon, and
rebuild templates before changing the enable flag.

## Regenerate

Run on a machine with Guix (writes a bare `.pub` and `.sec`):

```sh
guix repl <<'EOF'
(use-modules (gcrypt pk-crypto))
(let ((pair (generate-key
             (sexp->canonical-sexp
              '(genkey (ecc (curve Ed25519) (flags rfc6979)))))))
  (call-with-output-file "signing-key.pub"
    (lambda (p)
      (display (canonical-sexp->string (find-sexp-token pair 'public-key)) p)))
  (call-with-output-file "signing-key.sec"
    (lambda (p)
      (display (canonical-sexp->string (find-sexp-token pair 'private-key)) p))))
EOF
```
