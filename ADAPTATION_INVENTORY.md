# Adaptation Inventory

This file lists the Guix-specific adaptations that Qubes reviewers are most
likely to inspect.  It is not a substitute for reading the code; it is a map of
where behavior intentionally diverges from stock Qubes VM agent packaging.

## System Definition Adaptations

| Area | Code location | Adaptation | Rationale | Current validation |
| --- | --- | --- | --- | --- |
| Dom0-provided kernel | `qubes-dom0-kernel-bootloader`, system `bootloader`, `kernel`, and `initrd-modules` | Use a no-op bootloader record and a placeholder kernel package while building root images with `--no-bootloader`. | Qubes dom0 supplies the VM kernel; a native TemplateVM image should not pull in or install a guest bootloader stack. | Rootfs builds and inspections pass; nested-dom0/openQA boots use the dom0-provided kernel path. |
| Lean Guix base services | `%qubes-base-services-with-lean-udev`, `%qubes-omitted-base-service-types`, `%qubes-loopback-networking-services` | Keep Guix base services needed by the image, disable base services that conflict with Qubes VM startup, keep udev without bundled rules, and provide loopback-only static networking. | Qubes provides console, kernel, device, and network lifecycle through VM agents; Guix services should not race those assumptions. | Rootfs activation and nested-dom0/openQA smoke evidence exist for the current TemplateVM/AppVM scope; NetVM/ProxyVM behavior remains out of first-review scope. |
| Default Qubes user and privilege policy | system `users`, `groups`, `privileged-programs`, and `sudoers-file` | Provide the standard `user` account in `wheel` plus Qubes-related groups, keep Guix default setuid programs, and enable Qubes-style passwordless sudo. | Matches standard Qubes template defaults instead of inventing a Guix-specific login or sudo policy. | Rootfs activation and nested-dom0/openQA smoke run as the expected default user with standard privileged helper behavior. |

## Review Notes

- The adaptations above should remain small and Guix-specific.  If an upstream
  Qubes release removes the need for one, drop the local adaptation rather than
  carrying it forward.
- Source-changing substitutions are intentionally named by phase.  If Qubes
  maintainers prefer patch files, the source-edit rows above are the conversion
  candidates.
- `VALIDATION.md` is the source of truth for which adaptations have live
  TemplateVM/AppVM evidence and which are still only build/rootfs/module-load
  evidence.
